# OCOP Sales Copilot: technical MVP

This implementation keeps the existing Node/Express backend and Gemini provider.
Wikipedia remains a separate source of public cultural context. It is not a shop
inventory system or proof of a specific product's certification.

## Product retrieval

`product-knowledge.js` builds a small in-memory BM25 index from the authoritative
server catalogue's names, regions, descriptions and selling units. Queries retrieve
up to four relevant records for the Gemini system context. Product scope is applied
before retrieval. Records are labelled `shop_catalogue` and treated as untrusted
data. No certification year, health claim or historical story is generated by the
retriever. This is lexical retrieval, not embeddings or a vector database.

With the current small catalogue, local retrieval avoids another network request,
embedding costs and an additional database service. PDF/Word parsing and semantic
embeddings remain future extensions when actual source documents are available.

## Gemini function calling

`sales-tools.js` exposes `check_inventory` and `search_product_knowledge` for
inventory-related text chat. Inventory questions skip the separate intent-classifier
request and public Wikipedia lookup. It sends function declarations to Gemini, executes
only allowlisted functions, and returns function responses to the model. Full
model content is preserved, including thought signatures. At most two tool rounds
and four calls per round are allowed; the final answer uses the existing JSON
schema. Inventory requests have a 15-second total backend deadline; ordinary chat
keeps its existing deadline. Retries do not switch to another AI provider.

`create_draft_order` is offered only with explicit `confirmedDraft` frontend
confirmation. The function accepts no model-supplied customer or line-item data:
it uses the exact confirmation payload, which the store validates again. The
regular draft form calls the deterministic backend endpoint directly, so saving
a customer-approved draft does not depend on Gemini latency or availability.

Function-calling format follows Google's documentation:
https://ai.google.dev/gemini-api/docs/function-calling

## Inventory and draft storage

`sales-store.js` stores inventory and drafts in `.private-data/sales-store.json`
(override with `SALES_DATA_FILE`). Writes use a temporary file and atomic rename.
No sample stock is seeded: `stock: null` means the seller has not supplied it.
Inventory can be edited only through the existing authenticated admin session.

Draft creation validates product IDs, positive integer quantities, recipient
details, explicit consent and an idempotency key. Prices come from the server
catalogue, not the browser or model. Known insufficient inventory rejects new
drafts. Missing inventory permits a clearly marked draft awaiting seller review.
Repeated identical requests return the same draft; a changed request using the
same key is rejected. Shipping fee and final total remain null. Drafts do not
reserve stock, charge payment, or create confirmed orders.

This local JSON store is for a single-server MVP. Before running multiple server
instances, replace it with transactional database storage. Production hosting must
provide a persistent private disk; an ephemeral host can lose files on redeploy.

## User interfaces and endpoints

- `/draft-order.html`: customer confirmation form, linked from chat suggestions.
- `/admin` (also `/admin-sales.html`): prices, available inventory, private draft
  processing and conversation/support review; uses the
  existing `/api/admin/audio/login` admin authentication, including its configured
  password and login throttling. Admin login remains necessary after expiry.
- `GET /api/ai/shop-products`: authoritative catalogue prices and known stock.
- `POST /api/ai/draft-orders`: validated, idempotent draft creation.
- `PUT /api/admin/sales/inventory/:productId`: authenticated inventory update.
- `GET /api/admin/sales/drafts`: authenticated draft review.
- `PUT /api/admin/sales/products/:productId`: atomic price/stock updates.
- `POST /api/admin/sales/drafts/:id/action`: confirm, ship, complete, cancel, paid.
  Confirmation requires sufficient verified inventory, unchanged draft prices,
  and the seller's acknowledgement that shipping fees were agreed with the customer.
  Confirmation reserves stock once; cancelling an unpaid, unshipped order releases
  it once. Delivery and payment states are independent. Paid records require a
  seller-entered receipt reference; this is not automatic bank reconciliation.
- `GET /api/admin/sales/conversations`, `POST .../:id/resolve`: private conversation
  review and support resolution. Stores up to 500 sessions / 90 days, 60 recent
  messages per session in `.private-data/sales-conversations.json`; override via
  `SALES_CONVERSATIONS_FILE`. New requests for staff reopen resolved support cases.
- Customer catalogue/cart price display refreshes every 30 seconds while visible,
  preserving the current product search. Server prices also feed AI and new drafts.
- Separate KPI website at `http://localhost:3002`, started with `npm.cmd run start:kpi`:
  today / last 7 days / last 30 days / retained-history filters, hourly SVG chart,
  product recommendation/retrieval distribution, bilingual UI and CSV export.
  Metrics retain up to 90 days / 50,000 events in `.private-data/ai-metrics.json`
  (override with `AI_METRICS_FILE`; persistent storage is needed in production).
  Tool executions are recorded before subsequent model output, including execution
  failures and calls followed by a model failure. Unknown stock is not a tool error.

The public draft-creation response excludes customer details and idempotency keys.
Customer details are shown only in authenticated admin draft review. KPI telemetry
does not include customer messages, phone numbers or addresses. Conversation logs
are a separate private store behind administrator authentication.
RAG accuracy remains unmeasured until a labelled evaluation exists. Draft conversion
counts distinct consultation sessions with a new draft in the selected period,
divided by sessions active in that period. Same-tab session IDs survive navigation
to the draft form, are hashed in telemetry, and are never exposed by the KPI API.
Idempotent draft retries do not increase counts. Old unlinked drafts remain visible
as a separate all-time total; paid-order conversion is not inferred. Self-service
is a proxy (sessions without errors or staff requests), not verified resolution.
Business KPIs include seller-confirmed orders, completed deliveries and paid revenue
within each selected window. Chatbot revenue requires a verified consultation source,
not merely a client-supplied session string. Revenue includes agreed shipping fees;
unpaid drafts and delivery completion alone never increase paid revenue.

Run `npm.cmd start` for the local demo and `npm.cmd test` for the test suite.
Set the `ocop-api-base` meta tag on frontend pages when hosting them separately.
No Zalo/Messenger webhook or external database service is claimed as connected.
